# XTEINK X4 Pro: аппаратная база и безопасное тестирование

Ветка `dev-x4pro-test` предназначена исключительно для XTEINK X4 Pro. В ней нет
сборок для X3/X4 на ESP32-C3 и нет runtime-определения старых плат.

## Подтверждённая платформа

По дампу OEM-прошивки, документации FreeInk и аппаратному bring-up подтверждены:

| Узел | X4 Pro |
|---|---|
| MCU | ESP32-S3 |
| Flash / PSRAM | 16 МБ / 8 МБ octal |
| E-paper | 800 × 480, подтверждённый путь SSD1677 |
| Display SPI | SCLK12, MOSI11, CS13, DC18, RST14, BUSY6 |
| Touch | GT911: SDA39, SCL38, INT10, RST4, питание GPIO2 active-low |
| Кнопки | GPIO0, GPIO7, POWER GPIO3, active-low |
| SD | SDMMC 1-bit: CLK41, CMD42, DAT0=40, питание GPIO5 active-low |
| Gauge / RTC | CW2017 `0x63`, BM8563/PCF8563 `0x51` |
| Frontlight | GPIO8/GPIO9, LEDC 10 кГц, 10 bit |
| Master rail | GPIO1 HIGH до инициализации периферии |

Источники:

- [официальная спецификация и FAQ X4 Pro](https://www.xteink.com/blogs/product/x4-pro-faq-specs-support);
- [документы FCC 2BTR9-X4PRO](https://fccid.io/2BTR9-X4PRO);

## Разметка OEM

Проект использует исходную таблицу X4 Pro:

| Раздел | Offset | Size |
|---|---:|---:|
| nvs | `0x9000` | `0x5000` |
| otadata | `0xE000` | `0x2000` |
| app0 | `0x10000` | `0x7E0000` |
| app1 | `0x7F0000` | `0x7E0000` |
| spiffs | `0xFD0000` | `0x014000` |
| coredump | `0xFE4000` | `0x01C000` |

На исследованной заводской прошивке активен `app1`. Поэтому первый тест пишет
только неактивный `app0`. Запись объединённого образа с `0x0` запрещена: она
стирает индивидуальный NVS `hw_calib` и лишает устройство заводского отката.

## Защита дисплея

Перед `display.begin()` выполняется два независимых readback-пробника регистра
контроллера. В первой полевой сборке разрешён только результат
`PrimaryAssumed`, соответствующий проверенному SSD1677. Подтверждённый UC81xx
или неоднозначный ответ останавливает дисплей до подачи refresh-последовательности
и записывает `/.crosspoint/x4pro_panel_probe.txt` на SD.

Драйверы UC8179/UC8279, восстановленные из OEM-кода, остаются неподтверждёнными
на соответствующем физическом модуле. Они не должны автоматически включаться в
первом тесте.

## Обновление

Старый C3-механизм сырой записи разделов и обход проверки eFuse удалён из
X4 Pro-сборки. Код OTA и обновления с SD полностью исключён из первой полевой
ветки. Заголовок передаваемого внешнему установщику приложения проверяется на
chip ID `ESP32-S3 (0x0009)` до любой записи.

## Обязательный протокол тестера

Полные команды приведены в корневом `README.md`. Порядок не сокращается:

1. вход в ROM download mode;
2. `backup` — полный 16-МБ дамп и извлечение NVS/otadata/app1;
3. физическое переподключение и повторный вход в ROM;
4. `verify` — сравнение MAC, защищённых областей и factory app1;
5. `install` — app0, readback SHA-256, затем один резервный сектор otadata;
6. сохранение serial log и файла panel probe;
7. при проблеме — `restore-stock`, который проверяет весь заводской `app1` и
   записывает один неактивный сектор `otadata`, выбирающий заводской слот.

Сохранённый OEM bootloader не заменяется. Поэтому автоматический rollback нельзя
обещать, пока его конфигурация не подтверждена на конкретном устройстве. Предусмотренный
путь восстановления — заранее проверенный ROM download mode и `restore-stock`; он не
зависит от запуска тестовой прошивки.

До успешного выполнения первых пяти пунктов прошивку нельзя передавать как
обычный пользовательский релиз.
