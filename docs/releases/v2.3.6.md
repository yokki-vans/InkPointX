# InkPoint X v2.3.6

This release fixes the repeated black blink and multi-second delay reported on
XTEINK X3 units with a UC8253 display controller. Thanks to
[@mr-f0xx](https://github.com/mr-f0xx) for tracing the fault on hardware,
contributing the fix, and confirming that navigation is responsive again.

- The X3 driver no longer sends `PON` when the panel is already powered. On the
  affected units, that command never asserted BUSY, so each navigation frame
  timed out and fell back to a full refresh.
- The display path allows a longer BUSY-start interval and retries a start
  timeout with the same frame before resetting the controller. This also
  prevents a failed first attempt from leaving the boot image on screen until
  another keypress.
- Device QA builds add an EPD trace log and an on-device viewer under
  Settings → System. These diagnostics are disabled in the release build.

The fix spans [InkPointX #28](https://github.com/yokki-vans/InkPointX/pull/28)
and its [freeink-sdk companion](https://github.com/yokki-vans/community-sdk/pull/2).
The firmware remains a universal X3/X4 application image.

## Validation

The contributor's UC8253 X3 hardware test found no recurring blink or
`X3_PON` failure after the fix; navigation frames completed in approximately
200–400 ms. The host driver suite reported 220 passing tests. Release CI also
checks the production build, embedded version, localization, static analysis,
and OTA slot size. Other X3 panel revisions and X4 hardware have not been
physically verified for this change.

## Update

On an existing InkPoint X installation, connect to Wi-Fi and choose
**Settings → System → Check for updates**. The updater will offer v2.3.6 after
the release assets are published. For SD recovery, use `update.bin` with the
supported stock updater or `firmware.bin` with a compatible InkPoint X /
CrossPoint recovery picker. The X3 and X4-labelled downloads contain the same
image; verify them with `SHA256SUMS`.

These are application images, not full-flash dumps. Books and settings on the
microSD card are retained. A locked unit still needs a compatible SD or
application updater; this release does not unlock USB.
