# InkPoint X v2.3.5

Fixes display-state bugs that can leave X3/X4 content stale, corrupt a partial
refresh, or require another input after a failed refresh. This release is built
from `dev`, with a universal ESP32-C3 image for X3 and X4.

- X3 / UC8279D: restore the full 792 × 528 transfer window before every B/W
  frame, including after grayscale strips and region preconditioning.
- X3 / UC8279D: when controller RAM is unknown after reset/wake, drive every
  target pixel with the existing GC waveform instead of treating retained
  e-ink content as a valid previous-frame buffer.
- X3 / UC8253 and UC8279D: do not enable fast differential updates against RAM
  reset by initialization or overwritten by an unfinished grayscale operation.
  Propagate grayscale/power failures without marking an undisplayed frame valid.
- X3 / UC8253: preserve explicit FULL requests across power-on and cancel pending
  frame completion when the controller is reinitialized.
- X4 / UC8179: allow the same bounded BUSY-start interval as X3, honor CLEAN
  requests, invalidate RAM/pending state on reinitialization, and preserve the
  submitted framebuffer until its OLD-plane synchronization finishes.
- Shared bus: consume the observed BUSY-start state exactly once, including
  polling and low-memory fallbacks. A waveform that already finished must not
  wait for a second start edge.
- Retains runtime controller detection, including UC8279D blank-MTP modules and
  family-specific OEM calibration fallback. USB lock status is not used as a
  controller identifier. The SSD1677 waveform and X3/X4 button mappings are unchanged.

This follows the current `dev` line (including dark mode and the parser/memory
fixes merged after 2.3.4); it is not a changes-only rebuild of the 2.3.4 recovery
image.

## Validation and compatibility limits

220 host tests pass. Running the new driver/bus regression suite against the
previous SDK reproduces 14 failing scenarios, all passing with this SDK update.
The local `gh_release` build and `pio check --fail-on-defect medium` pass;
localization validation passes (28 locales, 12 UI fonts). The application is
6,534,160 bytes within the 6,553,600-byte OTA slot; its ESP descriptor reports
`v2.3.5`.

Tests exercise production C++ drivers and the production bus with simulated
GPIO/SPI; they do not measure physical panel timing or image quality.

Known code paths cover X3 UC8253, X3 UC8279D (including blank MTP), X4 SSD1677,
and X4 UC8179. No physical X3/X4 revision was flashed or optically verified for
this release. The exact device in the report has not been reproduced in hand.
Universal support for every undocumented hardware revision is not claimed.
See `docs/X3_X4_COMPATIBILITY.md` for the hardware acceptance matrix.

## Update

Use **Settings → OTA Update**, or use `firmware.bin` with a compatible existing
updater. `update.bin` is the identical application image with the filename
expected by supported SD recovery workflows. All device-labelled `.bin` files
are aliases of the same firmware; checksums are supplied in `SHA256SUMS`.

These are application images, not merged flash dumps: they do not replace the
bootloader or partition table. Existing books/settings are kept. A locked
unit still needs its existing compatible SD/application updater; this release
does not unlock USB. Automatic rollback depends on the installed bootloader
and partition configuration and is not guaranteed for SD recovery installs.
